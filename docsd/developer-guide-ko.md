# Skill Security Audit — 개발자 가이드

## 이게 무엇인가요?

이 리포를 처음 보면, 구조가 조금 낯설 수 있습니다.  
룰 문서도 있고, SKILL.md도 있고, GitHub Actions도 있습니다.

핵심만 정리하면 다음과 같습니다.

**이 프로젝트는 스킬을 배포하기 전에 자동으로 검사해주는 안전 장치입니다.**

---

## 왜 필요한가요?

Claude Code와 같은 환경에서 스킬은 단순한 함수가 아닙니다.

스킬은 다음과 같은 일을 할 수 있습니다:

- 쉘 명령 실행
- 파일 읽기/쓰기
- 외부 API 호출

즉, 잘못된 스킬 하나로도:

- API 키 유출
- `rm -rf` 같은 파괴적 명령 실행
- `curl | bash`로 외부 코드 실행

이 가능합니다.

이 리포는 이런 문제를 **PR 단계에서 자동으로 차단하거나 경고**하기 위해 만들어졌습니다.

---

## 어떻게 동작하나요?

전체 흐름은 간단합니다.

1. 개발자가 스킬을 PR로 제출
2. GitHub Actions 실행
3. 스킬 자동 검사
4. 결과 출력

결과는 세 가지로 나뉩니다:

- **CRITICAL → 차단 (merge 불가)**
- **HIGH / MEDIUM → 경고 (merge 가능)**
- **문제 없음 → 통과**

즉, 이 시스템은 **리뷰 전에 동작하는 1차 필터**입니다.

---

## 이 시스템의 핵심 철학

이 도구는 완벽한 보안을 목표로 하지 않습니다.

대신 다음을 목표로 합니다:

> “확실히 위험한 것만 막고, 나머지는 개발자가 개선하도록 한다”

너무 엄격하면 아무도 사용하지 않기 때문입니다.

그래서:

- 위험 확실 → 차단
- 애매함 → 경고

라는 구조를 취합니다.

---

## 내부 구조

이 시스템은 크게 세 부분으로 구성됩니다.

### 1. 오케스트레이터
`SKILL.md`

검사 흐름을 정의합니다.

---

### 2. 룰 정의
`references/` 폴더

다음과 같은 카테고리로 나뉩니다:

- 보안
- 파괴적 명령
- 메타데이터
- 품질
- 스펙 준수

---

### 3. CI 실행
GitHub Actions

PR에서 자동으로 검사 수행

---

## 실제 사용 시 경험

PR을 올리면 자동으로 피드백이 달립니다:

- “이건 credential leak 가능성이 있습니다”
- “shell injection 위험이 있습니다”
- “spec이 맞지 않습니다”

그리고 위험한 경우는 아예 merge가 막힙니다.

---
