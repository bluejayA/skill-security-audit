# Skill Security Audit — 보안 관점 개요

## 문제 정의

AI 에이전트 스킬은 기존 코드와 다른 특성을 가집니다.

- 사용자 입력을 처리하고
- 쉘을 실행하며
- 파일 시스템에 접근하고
- 네트워크로 데이터를 전송합니다

이 조합은 매우 넓은 공격면을 형성합니다.

문제는 이 리스크를 **수동 리뷰만으로 관리하기 어렵다는 점**입니다.

---

## 이 시스템의 역할

이 리포는 다음 문제를 해결하려 합니다:

> “스킬이 등록되기 전에 자동으로 검증하자”

즉, 역할은 다음과 같습니다:

- Admission Control
- 사전 검증 (Pre-deployment validation)
- CI 기반 정책 집행

---

## 시스템 구조

구조는 네 가지 레이어로 나뉩니다.

### 1. 정책 (Policy)
룰 체크리스트 정의

---

### 2. 실행 (Execution)
`SKILL.md`에서 감사 흐름 정의

---

### 3. 거버넌스 (Governance)
`audit-ignore` 기반 예외 관리

- reviewer 승인
- 사유 기록
- 만료 기반 통제

---

### 4. 실행 환경 (Enforcement)
GitHub Actions에서 자동 실행

---

## 핵심 설계 선택

가장 중요한 설계는 다음입니다:

> “CRITICAL만 차단한다”

이건 의도적인 선택입니다.

너무 엄격하면:

- false positive 증가
- 시스템 무력화

따라서:

- 확실한 위험만 차단
- 나머지는 가시성 확보

라는 전략을 취합니다.

---

## 위협 대응 범위

이 시스템이 커버하는 영역:

- Credential leakage
- Remote code execution
- Command injection
- Data exfiltration
- Privilege escalation
- Obfuscation (base64, unicode 등)

즉, **즉시 악용 가능한 위험** 중심입니다.

---

## 강점

- 정책과 실행 분리 구조
- CI 통합
- 예외 관리 체계 포함
- 감사 기록 유지
- 운영 가능한 수준의 현실적 설계

---

## 한계

다음과 같은 구조적 한계가 존재합니다:

- 패턴 기반 탐지 중심
- semantic 분석 부족
- 일부 fail-open 가능성
- 문서와 구현 간 불일치 가능성
- exception 모델이 reviewer 신뢰에 의존

---

## 이 시스템을 어떻게 봐야 하는가

이건 완전한 보안 솔루션이 아닙니다.

정확한 정의는 다음과 같습니다:

> “AI 스킬 생태계를 위한 1차 보안 통제 계층”

즉:

- 마지막 방어선 ❌
- 초기 필터 ✔

---

## 조직 관점에서의 변화

이 시스템 도입 시:

- 보안 정책이 코드화됨
- 검증이 자동화됨
- 위험이 더 이른 단계에서 제거됨
- 감사 추적 가능성 확보

즉, 보안이 **사후 대응 → 사전 통제**로 이동합니다.
